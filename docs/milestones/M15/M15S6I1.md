## Root Cause Analysis

### Issue 1: Approve Button Does Not Work

**Location**: `src/web/app.py:472`

The `/approve-idea/{item_id}` route handler has incorrect status validation logic:
```python
if item["status"] != "approved":
    raise HTTPException(status_code=400, detail="Content must be in 'approved' status")
```

However, the template `src/web/templates/partials/content_row.html:61` displays the Approve button for `idea` status:
```jinja2
{% if item.status == 'idea' %}
    <button hx-post="/approve-idea/{{ item.id }}">Approve</button>
```

Additionally, the update statement on line 476 sets status to 'approved' (same value check):
```python
await conn.execute("UPDATE content SET status = 'approved' WHERE id = $1", item_id)
```

**Root Cause**: Logic mismatch between template and handler:
- Template shows button for `idea` status items
- Handler expects `approved` status to approve
- Status transition logic is inverted (should transition from `idea` → `approved`)

### Issue 2: Registry Screen Returns "Registry file not found"

**Location**: `src/web/app.py:167`

The registry file path is computed incorrectly:
```python
registry_path = Path(__file__).parent.parent.parent / "autonomedia" / "content" / "mention_registry.json"
```

This resolves to:
```
/autonomedia-snapshot/autonomedia/content/mention_registry.json ❌ Does NOT exist
```

But the actual file exists at:
```
/autonomedia-snapshot/src/autonomedia/content/mention_registry.json ✅ Exists
```

**Evidence**: Shell verification confirms path mismatch:
```
Computed path: /autonomedia-snapshot/autonomedia/content/mention_registry.json
Exists: False

Correct path: /autonomedia-snapshot/src/autonomedia/content/mention_registry.json
Exists: True
```

**Root Cause**: Path navigation off by one level - `.parent.parent.parent` navigates to `/autonomedia-snapshot/` instead of `/autonomedia-snapshot/src/`.

### Issue 3: Platforms Page Shows Empty

**Location**: `src/web/app.py:232-233` and `src/web/templates/platforms.html:11`

The SQL query returns `is_healthy` as a boolean column:
```python
platform_health = await conn.fetch(
    "SELECT platform_name, is_healthy FROM platform_health ORDER BY platform_name"
)
```

But template expects `status` field:
```jinja2
{% if h.status == 'healthy' %}
```

**Evidence**: Template field mismatch causes empty display since `is_healthy` is boolean (True/False) not string ("healthy"/"unhealthy").

**Root Cause**: Field name mismatch between database column (`is_healthy`) and template expectation (`status`). The handler in `get_platform_health()` function does map this correctly for sidebar, but `platforms_page()` does not.
