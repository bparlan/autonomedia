# Verification Protocol M15S10
| Property      | Value           |
| ------------- | --------------- |
| Document Type | Verification Protocol |
| Identifier    | M15S10V         |
| Derived From  | M15S10          |
| Scope         | AI Rewriting & Platform Handler Fixes |

## Success Criteria

*   **AI Rewriting Functionality:**
    *   [ ] Ideas approved in the UI trigger AI rewriting.
    *   [ ] AI successfully generates platform-specific content drafts for LinkedIn, X, and Mastodon.
    *   [ ] Content status correctly transitions through 'approved', 'rewriting', 'prepared', and 'ready_to_post'.
    *   [ ] Errors during AI rewriting are handled gracefully, logged, and result in 'failed' status.
*   **Platform Handler Correctness:**
    *   [ ] LinkedIn handler typo is fixed.
    *   [ ] X handler bugs (rate limiting, batch post results) are fixed.
    *   [ ] Mastodon handler functions correctly.
    *   [ ] Platform handlers correctly implement content adaptation and validation.
*   **Documentation and UI Completeness:**
    *   [ ] "Platform Status" page displays detailed platform information (limits, tone, auth, rate limits).
    *   [ ] `/platform-status` API returns comprehensive platform data.
    *   [ ] Platform-specific requirements are documented according to M15S2 and M15S3.
*   **Workflow Integrity:**
    *   [ ] The end-to-end flow from Idea > Approval > Rewrite > Verification > Posting is functional.
    *   [ ] All specified tests (unit, integration, E2E) pass.

## Functional Validation

### AI Rewriting Pipeline Implementation

*   **FR1.1:** Integrate a concrete AI provider.
    *   **Input:** A prompt and context for AI rewriting.
    *   **Expected Output:** A successfully rewritten content draft in the correct format.
    *   **Method:** Unit test for the `RewriteProvider` implementation (e.g., `GeminiProvider`), integration test with the `PostingSecretary` worker.
    *   **Requirement ID:** FR1.1
*   **FR1.2:** Correctly invoke AI functionality from `PostingSecretary` worker.
    *   **Input:** Content with 'idea' or 'approved' status.
    *   **Expected Output:** `self.provider.rewrite()` is called with correct parameters.
    *   **Method:** Unit test for `PostingSecretary.process_new_ideas`.
    *   **Requirement ID:** FR1.2
*   **FR1.3:** Generate platform-specific content adhering to constraints.
    *   **Input:** An idea and target platforms (LinkedIn, X, Mastodon).
    *   **Expected Output:** Rewritten content adheres to character limits, tone, and formatting rules for each platform.
    *   **Method:** Integration test, manual review of generated content.
    *   **Requirement ID:** FR1.3
*   **FR1.4:** Handle AI errors gracefully.
    *   **Input:** Simulate AI provider returning malformed or error response.
    *   **Expected Output:** Content status set to 'failed', error logged.
    *   **Method:** Unit test for `PostingSecretary.process_new_ideas` error handling.
    *   **Requirement ID:** FR1.4
*   **FR1.5:** Correct status transitions.
    *   **Input:** Various scenarios (successful rewrite, AI error, validation error).
    *   **Expected Output:** Content status transitions correctly ('idea' -> 'rewriting' -> 'prepared' or 'failed').
    *   **Method:** Unit test for status transition logic in `PostingSecretary.process_new_ideas`.
    *   **Requirement ID:** FR1.5
*   **FR1.6:** UI triggers AI rewriting.
    *   **Input:** User action: Click "Generate Rewrites" button.
    *   **Expected Output:** `/batch-generate` endpoint is called, initiating AI process.
    *   **Method:** Manual UI test, check network requests.
    *   **Requirement ID:** FR1.6
*   **FR1.7:** `/batch-generate` endpoint invokes AI process.
    *   **Input:** POST request to `/batch-generate`.
    *   **Expected Output:** AI rewriting is initiated, content status updated.
    *   **Method:** Integration test for the `/batch-generate` endpoint.
    *   **Requirement ID:** FR1.7

## Edge Cases

*   **AI Rewriting:**
    *   Empty input idea text.
    *   AI response with only whitespace.
    *   AI response exceeding platform character limits (test `adapt_content_for_platform` and handler truncation).
    *   AI response missing required fields (title, summary, tags for LinkedIn).
    *   AI response containing malicious/invalid characters.
*   **Platform Handlers:**
    *   LinkedIn: Test with content that requires title extraction and tag formatting.
    *   X: Test with content that requires truncation, hashtag formatting (camelCase), hook preservation, and link handling.
    *   Mastodon: Test with content requiring title/summary extraction, hashtag formatting, and link preservation.
    *   Authentication failures (invalid tokens, expired sessions).
    *   Rate limit errors triggering retries.
    *   Maximum retry attempts reached for any platform.
*   **Data Flow:**
    *   Race conditions when multiple processes try to update content status simultaneously.
    *   Database connection failures during status updates or content retrieval.

---

## Failure Scenarios (Negative Cases)

*   **AI Service Unavailability:** Test how the system responds when the AI provider API is down or returns persistent errors.
*   **Platform API Errors:**
    *   Simulate platform API returning `4xx` or `5xx` errors beyond rate limits.
    *   Test cases where platform APIs change unexpectedly.
*   **Resource Exhaustion:**
    *   Simulate high load to test memory usage of handlers and the posting routine.
    *   Test disk space issues if browser profiles or logs cannot be written.
*   **Invalid Configuration:**
    *   Missing or invalid platform API keys/tokens.
    *   Incorrectly configured browser profile paths.
*   **Security Violations:**
    *   Attempting to inject malicious code into content ideas or prompts.
    *   Exposing sensitive data (tokens, user info) through logs or error messages.

## Security Considerations

*   **Input Validation:** Validate all inputs to AI rewriting prompts and platform handlers to prevent injection attacks.
*   **Authorization:** Ensure that only authorized users can approve ideas and trigger posting workflows.
*   **Data Exposure:** Verify that no sensitive data (API keys, tokens, user data) is exposed in logs, error messages, or client-side JavaScript.
*   **Dependency Vetting:** Ensure all new AI or platform-related dependencies are security-audited.
