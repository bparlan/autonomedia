## Root Cause Analysis

### Issue 1: Approve Button Has No Visual Feedback

**Location**: `src/web/app.py:525-545` and `src/web/templates/partials/content_row.html:62`

The `approve_idea()` handler returns HTML fragment, but the template uses:
```jinja2
<button hx-post="/approve-idea/{{ item.id }}" hx-target="#row-{{ item.id }}" hx-swap="outerHTML">Approve</button>
```

**Root Cause**: 
- Handler returns updated item with status='approved' 
- Template renders "Generating" status badge for approved items
- No spinner/loading state during async operation
- User sees no immediate feedback

### Issue 2: AI Rewrites Items Become Invisible After Few Seconds

**Location**: `src/web/templates/partials/content_row.html:26` and `src/web/app.py:411-425`

The status cell has automatic polling:
```jinja2
{% if item.status in ['approved', 'rewriting'] %}hx-get="/status-fragment/{{ item.id }}" hx-trigger="every 5s"{% endif %}
```

But `status_fragment()` returns hardcoded inline HTML instead of querying actual status.

**Root Cause**:
- Polling every 5 seconds triggers status updates
- `status_fragment()` returns `<td>` element only, not full `<tr>` 
- HTMX replaces `<td>` with `<td>` causing the entire row's status cell to be replaced
- Since the query in `status_fragment()` was removed, it returns empty or broken markup

### Issue 3: Reset Status Button Loads Entire App

**Location**: `src/web/app.py:548-565`

The `reset_failure()` handler still returns:
```python
return RedirectResponse(url="/content", status_code=303)
```

But the template uses:
```jinja2
<button hx-post="/reset-failure/{{ item.id }}" hx-target="#row-{{ item.id }}" hx-swap="outerHTML">Reset Status</button>
```

**Root Cause**: Same as issue 1 - redirect returned to row-targeted HTMX causes page load inside row.
