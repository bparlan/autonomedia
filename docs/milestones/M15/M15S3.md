## Objective

Comprehensively document platform-specific requirements, content adaptation guidelines, and best practices for LinkedIn, X, and Mastodon to ensure operators understand platform constraints, optimize content strategy, and maintain compliance with platform norms.

---

## Functional Requirements

### Platform Requirements Documentation

**FR1.1**: The system shall maintain `docs/platform_requirements.md` with complete documentation for all three platforms.

**FR1.2**: Documentation shall include:
- Platform name and official branding (LinkedIn, X, Mastodon)
- Character limits and field requirements
- API requirements and authentication flows
- Rate limits and backoff strategies
- Content sharing advice and tone guidelines
- Cultural norms and formatting rules
- Platform-specific examples

**FR1.3**: Documentation shall be kept up-to-date with platform changes and published updates.

### LinkedIn Documentation

**FR2.1**: Documentation shall specify LinkedIn posting requirements:
- Maximum title length: 300 characters (no trailing period)
- Maximum summary length: 3,000 characters (supports paragraphs)
- Maximum tags: 5 tags (25 characters each, no duplicates)
- Character limits per field (title + summary + tags)
- Content format requirements (professional tone, 2-4 sentences per post)
- Link requirements (must include "See full article" link)

**FR2.2**: Documentation shall include LinkedIn-specific best practices:
- Professional tone guidelines
- How to structure title and summary
- Tag strategy (relevant, not spammy)
- When to include article links
- Frequency recommendations (max 1-2 posts per day per account)

**FR2.3**: Documentation shall provide LinkedIn-specific examples:
- Example title: "New Research Shows AI Safety Techniques Reduce Risks by 40%"
- Example summary: "Our latest study examines reinforcement learning alignment methods..."
- Example tags: ["AI Safety", "Machine Learning", "Alignment", "Research", "NLP"]

### X (Twitter) Documentation

**FR3.1**: Documentation shall specify X posting requirements:
- Maximum content length: 280 characters
- Maximum hashtags: 3 hashtags per post
- Hashtag formatting rules (#Hashtag camelCase)
- Content structure requirements (strong hook in first line)
- Tone guidelines (short, punchy, conversational)
- Thread creation guidelines

**FR3.2**: Documentation shall include X-specific best practices:
- How to craft strong hooks (first 3 words should grab attention)
- Hashtag strategy (1-2 hashtags per post)
- When to create threads vs. single posts
- Frequency recommendations (max 10 tweets per day per account)
- How to handle deleted or flagged tweets

**FR3.3**: Documentation shall provide X-specific examples:
- Short, punchy post: "🚀 AI safety is moving fast. New research shows alignment techniques reduce risks by 40%."
- Thread starter: "3 key insights from today's AI safety conference:"
- Hashtag example: "#MachineLearning #AI #Alignment"

### Mastodon Documentation

**FR4.1**: Documentation shall specify Mastodon posting requirements:
- Character limit: Unrestricted (as of current spec)
- Content format: Markdown supported (existing behavior)
- Tag requirements: Similar to X (camelCase, max 3 tags)
- Tone guidelines: Current Mastodon behavior maintained
- No changes to existing behavior

**FR4.2**: Documentation shall include Mastodon-specific best practices:
- Current behavior validation
- Community guidelines and norms
- Hashtag usage strategy
- Mastodon-specific features (boosts, favorites)

**FR4.3**: Documentation shall provide Mastodon-specific examples:
- Same content format as before
- Markdown support examples
- Current behavior validation examples

### Content Adaptation Guidelines

**FR5.1**: Documentation shall define content adaptation workflow:
- Input content (markdown) → Adapt per platform → Output per platform
- Use unified API to adapt content automatically
- Operator can manually adjust before publishing
- Content never cross-posted identically across platforms

**FR5.2**: Documentation shall specify when to use manual vs. automatic adaptation:
- Automatic adaptation: Standard content, clear platform target
- Manual adaptation: Complex content, special formatting needs
- Manual review: Always final step before publishing

**FR5.3**: Documentation shall include content adaptation rules:
- LinkedIn: Extract title, truncate summary, generate tags
- X: Strip markdown, truncate to 280 chars, format hashtags
- Mastodon: Keep existing behavior, minor formatting adjustments

### AI Detection & Compliance

**FR6.1**: Documentation shall include AI detection compliance guidelines:
- Avoid overuse of exclamation marks
- Avoid repetitive sentence structures
- Use natural language patterns (contractions, idioms)
- Avoid AI vocabulary (ensure, leverage, robust, cutting-edge)
- Use varied sentence lengths and structures

**FR6.2**: Documentation shall specify anti-detection best practices:
- Randomize posting times (within reasonable hours)
- Vary content length (LinkedIn 200-3000 chars, X 10-280 chars)
- Use human-like formatting (paragraph breaks, emojis sparingly)
- Avoid predictable patterns (same time daily, same structure)

**FR6.3**: Documentation shall include content quality guidelines:
- Focus on substance over formatting
- Use real examples and data
- Avoid "promotion-first" language
- Engage with questions and discussion

### Rate Limit & Authentication Documentation

**FR7.1**: Documentation shall specify rate limits for all platforms:
- LinkedIn: 1 post per 1-2 hours per account (estimated)
- X: 3,000 posts per 24 hours per account (updated: 10 posts per day)
- Mastodon: None (estimated)

**FR7.2**: Documentation shall define backoff strategies:
- Exponential backoff: Start with 1 second, multiply by 2 each retry
- Maximum backoff: 5 minutes between attempts
- Retry limit: 3 attempts for transient failures
- Rate limit response handling: Wait, then retry with backoff

**FR7.3**: Documentation shall specify authentication requirements:
- LinkedIn: OAuth 2.0 flow or API token
- X: OAuth 2.0 flow or API token
- Mastodon: OAuth 2.0 flow or API token
- Token storage: Environment variables or encrypted vault
- Token refresh: Easy reauthentication from platform management panel

### Cultural Norms & Formatting

**FR8.1**: Documentation shall document platform-specific cultural norms:
- LinkedIn: Professional, informative, respect for audience
- X: Conversational, brevity-focused, engagement-focused
- Mastodon: Community-focused, no character limits, slower pace

**FR8.2**: Documentation shall specify formatting rules:
- LinkedIn: Paragraph breaks for readability, professional formatting
- X: No paragraph breaks (280 characters), use line breaks for threads
- Mastodon: Markdown supported, can use paragraphs

**FR8.3**: Documentation shall include emoji usage guidelines:
- LinkedIn: Professional emojis (dots for bullets, checkmarks for checklists)
- X: Friendly emojis (fewer, punchy)
- Mastodon: Same as X, can use more due to length

## Data Flow

1. **Content Ingestion**: User or AI generates content in markdown format
2. **Platform Selection**: Content tagged with target platform(s)
3. **Adaptation**: Unified API adapts content per platform (title extraction, truncation, formatting)
4. **Review**: Operator reviews adapted content
5. **Publishing**: Content posted to selected platform(s)
6. **Feedback**: Operator provides feedback on content performance

**Data Structures**:
- `ContentInput` dict: `{platform: str, content: str, metadata: dict}`
- `ContentAdaptation` dict: `{platform: str, title: str, summary: str, tags: str, formatted_content: str}`
- `PlatformFeedback` dict: `{platform: str, engagement: dict, content_quality: dict, feedback: str}`

## Constraints

- **Platform Limitations**: Only LinkedIn, X, and Mastodon documented (no Instagram, TikTok, etc.)
- **Content Adaptation**: Content never cross-posted identically across platforms
- **Documentation Accuracy**: Documentation must reflect platform changes accurately
- **Tone Guidelines**: Documentation tone should match target platform tone (professional for LinkedIn, conversational for X, community-focused for Mastodon)
- **Currency**: Documentation must be kept up-to-date with platform changes
- **Examples**: Examples must be realistic and representative of actual usage
