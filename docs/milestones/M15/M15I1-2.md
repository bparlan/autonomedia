## Root Cause Analysis

### Primary Issue: Missing Route Definitions

All menu buttons in the HTML frontend (except "Command Center") return `{"detail":"Not Found"}` because their corresponding routes are not implemented in `src/web/app.py`.

### Menu Routes (in `src/web/templates/base.html`):
- `/content` → Content Domain page (doesn't exist)
- `/rewrites` → AI Rewrites page (doesn't exist)
- `/registry` → Registry page (doesn't exist)
- `/platforms` → Platforms page (doesn't exist)

### Current State
The current `src/web/app.py` is a minimal stub with only two endpoints:
- `GET /` → Dashboard (Command Center) ✅
- `GET /health` → Health check ✅

### Missing Endpoints (from original implementation in commit ef06942):

## Architecture Assessment

### Regression Risk: **MEDIUM**

**Risks:**
1. Menu and navigation functionality is completely broken - users cannot use the main UI
2. Missing database integration may expose ORMs if re-implemented incorrectly
3. Reintroducing 18+ routes requires careful re-implementation of existing functionality
4. Templates reference specific data structures (prepared_content JSON, verification_status JSON) that must match DB schema

**Architectural Constraints:**
1. Must use `DatabaseClient` from `src/database/client.py` for all DB operations
2. Must use Jinja2 with `Environment(loader=FileSystemLoader(...))` - Starlette's `Jinja2Templates` causes unhashable dict errors
3. Database schema must match SQL queries from original implementation
4. All endpoints must handle both HTML and potential JSON responses

**Design Pattern Adherence:**
- Original implementation used FastAPI with async handlers and asyncpg
- Template rendering uses direct Jinja2 calls (not `TemplateResponse`) to avoid Starlette caching issues
- Routes follow REST conventions for CRUD operations
- Form data handled via FastAPI's `Form` parameter
