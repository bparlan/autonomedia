## Objective

The specification for M18S3 establishes the comprehensive verification and testing framework for the infrastructure health dashboard, ensuring observability, reliability, and non-regression of the dashboard functionality through automated test suites.

## Functional Requirements

### FR-DASHBOARD_ACCESSIBILITY

**Type**: Browser/API Contract
**Interface Contract**: `GET /health` web endpoint must return 200 OK with accessible health status JSON/UI.

**Expected Behavior**:
- HTTP GET request to `/health` returns 200 OK
- Response contains HTML rendering of health dashboard
- Browser accessibility snapshot contains status indicators for:
  - Database health (healthy/unhealthy)
  - Runtime directories health (healthy/unhealthy)
  - Test suite health (healthy/unhealthy)
  - Source integrity health (healthy/unhealthy)
- No console errors during page load

**Observable Boundary**: Browser accessibility snapshot or API health check must return valid status with all four component indicators.

### FR-DASHBOARD_DATA_CONSISTENCY

**Type**: Test Contract
**Interface Contract**: Automated test verifies `/api/health` endpoint returns status consistent with backend `healthcheck.py` results.

**Expected Behavior**:
- Test suite runs `GET /api/health` endpoint
- Test compares endpoint JSON against `healthcheck.py` raw output
- Test validates all four components (database, runtime, tests, src) have consistent status values
- Test fails if endpoint and healthcheck results disagree
- Test runs on every dashboard deployment

**Observable Boundary**: Test must assert endpoint JSON fields match healthcheck output fields exactly.

### FR-LEGACY_CHECKS_REMOVAL

**Type**: Filesystem Contract
**Interface Contract**: All legacy `scripts/checks/` directory files must be archived or deleted.

**Expected Behavior**:
- No files remain in `scripts/checks/` directory
- Legacy checks are replaced by dashboard status indicators
- Archive location is `_archive/scripts/checks/` if retention required

**Observable Boundary**: Directory listing of `scripts/checks/` must return empty.

### FR-RUNTIME_SESSIONS_FIX

**Type**: Integration Contract
**Interface Contract**: `runtime/sessions` directory must be resolved or initialization logic must handle existing issues.

**Expected Behavior**:
- Dashboard does not report runtime directory as unhealthy due to `runtime/sessions` issues
- Existing initialization logic prevents directory-related errors
- Status indicator for runtime reflects true operational state

**Observable Boundary**: Dashboard runtime status must not be marked unhealthy due to sessions directory problems.

## Non-Functional Requirements

### NFR-TEST_COVERAGE

**Constraint**: Test suite must cover all dashboard paths: accessibility, data consistency, legacy removal, and runtime sessions.

**Verification**: Code coverage report must show 100% coverage of dashboard component functions and endpoint handlers.

### NFR-REGRESSION_PREVENTION

**Constraint**: Dashboard modifications must not break existing health indicators or cause regression in accessibility.

**Verification**: Regression test suite runs before any dashboard changes.

### NFR-ERROR_SIGNALING

**Constraint**: Dashboard must expose clear error states when infrastructure healthchecks fail.

**Verification**: Error states are visible in UI and accessible via API.

- `healthcheck.py` utility exists and returns valid status outputs

- Existing dashboard UI is functional and accessible

## Acceptance Criteria

- E2E test passes: `/health` page loads with all four component indicators
- Integration test passes: `/api/health` JSON matches `healthcheck.py` output
- Unit test suite passes: All dashboard component functions are tested
- Legacy checks archived: `scripts/checks/` directory empty or contains only archive
- Runtime sessions handled: Dashboard runtime status not marked unhealthy due to sessions
- Test coverage meets 100% for dashboard component functions
- No regression: Existing functionality not broken by new tests
