## Root Cause Analysis

The original specification (M18S1) required using the `health.jsx` React component. The implementation attempted:
1. **Babel Standalone CDN** with `type="text/babel"` for JSX transformation
2. **Dynamic ES Module import** (`import('/autogen/...')`) to load the component

Both approaches failed because:
- Browser ES Modules require proper CORS headers and MIME types (`application/javascript`)
- FastAPI's StaticFiles doesn't automatically set correct MIME types for `.jsx` files
- Babel Standalone JSX transformation in browser has limited error reporting
- No network errors were visible, just silent render failure

---

## Solution Applied

**Inline React Component** approach:
- Uses `React.createElement()` directly instead of JSX
- No Babel transformation needed
- No dynamic import needed
- Only requires React and ReactDOM CDNs
- Eliminates all browser-side tooling dependencies

This is a pragmatic fix that delivers the functional requirements while maintaining compatibility with the CDN-only setup.

## Lessons Learned

1. **Avoid browser-side tooling** for production components when possible - CDN-only setups are fragile
2. **Dynamic ES Module imports** require proper server configuration (CORS, MIME types)
3. **Inline `React.createElement()`** is more reliable than Babel JSX for simple components
4. **Always verify the server is running** before evaluating tests - environment pre-conditions matter
5. **Deprecated files** should be actively removed to prevent confusion (server.py was serving old template)
