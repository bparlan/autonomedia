### VER-M18S1V-01: FR-STATUS_ENDPOINT_INIT
- **Source Requirement ID**: FR-STATUS_ENDPOINT_INIT
- **Verification Method**: SCRIPT_EXECUTION
- **Target**: GET /api/health endpoint
- **Preconditions**: Autonomedia web server is running on localhost:port (default)
- **Input**: None
- **Expected Evidence**: 
  - HTTP status code 200
  - JSON response containing keys: "database", "runtime", "tests", "src"
  - Each value is either "healthy" or "unhealthy"
- **Failure Condition**: 
  - HTTP status code != 200
  - Missing any required key
  - Any value not in ["healthy", "unhealthy"]
- **Initial Failure Expectation**: 
  - Before implementation, the endpoint does not exist, so a curl request will fail to connect (exit code 7) or return an error status handled by the test script (exit code 1).
- **Post-Implementation Success Expectation**: 
  - Test script exits with code 0 when all evidence conditions are met.

### VER-M18S1V-02: FR-DASHBOARD_UI_INIT
- **Source Requirement ID**: FR-DASHBOARD_UI_INIT
- **Verification Method**: SCRIPT_EXECUTION
- **Target**: GET /health endpoint (dashboard page)
- **Preconditions**: Autonomedia web server is running on localhost:port (default)
- **Input**: None
- **Expected Evidence**: 
  - HTTP status code 200
  - HTML response contains a container element for the dashboard (e.g., `<div id="health-dashboard">` or similar)
- **Failure Condition**: 
  - HTTP status code != 200
  - Missing expected dashboard container element
- **Initial Failure Expectation**: 
  - Before implementation, the /health route does not exist, so a curl request will fail to connect (exit code 7) or return an error status handled by the test script (exit code 1).
- **Post-Implementation Success Expectation**: 
  - Test script exits with code 0 when the dashboard page returns 200 and contains the expected container.

### VER-M18S1V-03: FR-DASHBOARD_DATA_BINDING
- **Source Requirement ID**: FR-DASHBOARD_DATA_BINDING
- **Verification Method**: SCRIPT_EXECUTION
- **Target**: Dashboard UI fetches data from /api/health and displays status
- **Preconditions**: 
  - Autonomedia web server is running on localhost:port (default)
  - The /api/health endpoint is accessible and returns JSON
- **Input**: None (the dashboard performs the fetch)
- **Expected Evidence**: 
  - The dashboard HTML contains status indicators that correspond to the values in the JSON from /api/health.
  - For each component (database, runtime, tests, src), there is an element whose class or text reflects the health value (e.g., a class "healthy" or "unhealthy", or text "Healthy"/"Unhealthy").
- **Failure Condition**: 
  - Any component's displayed status does not match the corresponding value from the API JSON.
  - Missing status indicator for any component.
- **Initial Failure Expectation**: 
  - Before implementation, the dashboard does not fetch data or does not display correct status, so the verification script will detect a mismatch (exit code 1).
- **Post-Implementation Success Expectation**: 
  - Test script exits with code 0 when all displayed statuses match the API JSON values.
