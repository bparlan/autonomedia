## Verification Items

### VER-01: Dashboard Accessibility Verification

**Source Requirement**: FR-DASHBOARD_ACCESSIBILITY

**Verification Method**: SCRIPT_EXECUTION

**Target**: `/health` web endpoint

**Preconditions**:
- Autonomedia web server is running
- Browser headless test infrastructure is available

**Input**: GET request to `http://localhost:8000/health`

**Expected Evidence**:
- HTTP 200 OK status code
- HTML content with accessibility snapshot containing:
  - Database health indicator (text containing "healthy" or "unhealthy")
  - Runtime directories health indicator
  - Test suite health indicator
  - Source integrity health indicator
  - No console error logs

**Failure Condition**: Test assertion fails if any component indicator is missing or status is invalid

**Initial Failure Expectation**: Exit code 127 (Command not found) or 1 (Test execution failure)

**Post-Implementation Success Expectation**: All assertions pass, console errors absent

**Test File**: `tests/e2e/health_dashboard_test.py`

### VER-02: Dashboard Data Consistency Verification

**Source Requirement**: FR-DASHBOARD_DATA_CONSISTENCY

**Verification Method**: SCRIPT_EXECUTION

**Target**: `/api/health` endpoint vs `healthcheck.py` utility

**Preconditions**:
- Autonomedia web server is running
- `healthcheck.py` utility exists and returns valid status
- Backend healthcheck utility produces deterministic output

**Input**: 
- `GET http://localhost:8000/api/health`
- Run `healthcheck.py` utility to get baseline status

**Expected Evidence**:
- `/api/health` returns JSON with fields: `database`, `runtime`, `tests`, `src`
- All four fields have values "healthy" or "unhealthy"
- `/api/health` JSON values exactly match `healthcheck.py` output values

**Failure Condition**: Assertion fails if endpoint JSON fields don't match healthcheck output or status values are invalid

**Initial Failure Expectation**: Exit code 1 (assertion failure) - API endpoint or healthcheck utility not implemented

**Post-Implementation Success Expectation**: Test passes confirming endpoint data matches healthcheck output exactly

**Test File**: `tests/integration/health_endpoint_test.py`

### VER-03: Legacy Checks Removal Verification

**Source Requirement**: FR-LEGACY_CHECKS_REMOVAL

**Verification Method**: SCRIPT_EXECUTION

**Target**: `scripts/checks/` directory

**Preconditions**:
- Legacy checks files exist to be archived

**Input**: Directory listing command `ls -la scripts/checks/`

**Expected Evidence**:
- Directory returns empty or only contains `_archive/` subdirectory
- No legacy check files present in `scripts/checks/`

**Failure Condition**: Assertion fails if any legacy check files remain in `scripts/checks/`

**Initial Failure Expectation**: Exit code 1 (assertion failure) - files still present, not archived

**Post-Implementation Success Expectation**: All legacy check files archived, directory empty

**Test File**: `tests/e2e/health_dashboard_test.py`

### VER-04: Runtime Sessions Fix Verification

**Source Requirement**: FR-RUNTIME_SESSIONS_FIX

**Verification Method**: SCRIPT_EXECUTION

**Target**: `runtime/sessions` directory initialization

**Preconditions**:
- `runtime/sessions` directory exists or initialization logic runs

**Input**: Fetch `/api/health` endpoint and check `runtime` status

**Expected Evidence**:
- Dashboard `runtime` status indicator shows "healthy" (not "unhealthy")
- Status reflects true operational state, not `runtime/sessions` issues

**Failure Condition**: Assertion fails if `runtime` status is "unhealthy" due to sessions directory problems

**Initial Failure Expectation**: Exit code 1 (assertion failure) - runtime status incorrect or errors present

**Post-Implementation Success Expectation**: Runtime status correctly reflects operational state without false negatives

**Test File**: `tests/integration/health_endpoint_test.py`

### VER-05: Test Coverage Verification

**Source Requirement**: NFR-TEST_COVERAGE

**Verification Method**: SCRIPT_EXECUTION

**Target**: Dashboard component code coverage

**Preconditions**:
- Test suite executed

**Input**: `pytest --cov=src/autonomedia/web/ui/dashboard --cov-report=html`

**Expected Evidence**:
- Coverage report shows 100% coverage for dashboard component functions
- HTML coverage report generated at `htmlcov/index.html`

**Failure Condition**: Coverage percentage < 100%

**Initial Failure Expectation**: Exit code 1 (coverage < 100%) - insufficient test coverage

**Post-Implementation Success Expectation**: All dashboard component functions covered, coverage meets 100%

**Test File**: `pytest --cov=src/autonomedia/web/ui/dashboard --cov-report=html`

### VER-06: Regression Prevention Verification

**Source Requirement**: NFR-REGRESSION_PREVENTION

**Verification Method**: SCRIPT_EXECUTION

**Target**: Dashboard component regression tests

**Preconditions**:
- Existing dashboard functionality stable

**Input**: `pytest tests/e2e/health_dashboard_test.py tests/integration/health_endpoint_test.py`

**Expected Evidence**:
- All existing dashboard tests pass
- No test failures indicating regression in accessibility or health indicators

**Failure Condition**: Any existing test fails indicating regression

**Initial Failure Expectation**: Exit code 1 (test failure) - regression detected or tests broken

**Post-Implementation Success Expectation**: All dashboard tests pass, no regressions introduced

**Test File**: `pytest tests/e2e/health_dashboard_test.py tests/integration/health_endpoint_test.py`

### VER-07: Error Signaling Verification

**Source Requirement**: NFR-ERROR_SIGNALING

**Verification Method**: SCRIPT_EXECUTION

**Target**: Dashboard error states

**Preconditions**:
- `healthcheck.py` returns "unhealthy" for some components

**Input**: Fetch `/api/health` endpoint with unhealthy status

**Expected Evidence**:
- Dashboard displays error state for unhealthy components
- Error state visible in UI (red indicator or error message)
- API returns clear error code (e.g., 500) or error field for unhealthy components

**Failure Condition**: Assertion fails if unhealthy components don't show error state or API returns unclear error

**Initial Failure Expectation**: Exit code 1 (assertion failure) - error states not properly exposed

**Post-Implementation Success Expectation**: Unhealthy components show clear error states in UI and API

**Test File**: `tests/e2e/health_dashboard_test.py`
