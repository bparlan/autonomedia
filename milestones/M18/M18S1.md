## Objective
Develop a unified, web-accessible infrastructure health dashboard for the Autonomedia system, providing real-time status of database, runtime directories, test suite integrity, and source availability, powered by a new structured API endpoint.

## Functional Requirements (FRs)

### FR-STATUS_ENDPOINT_INIT
The system MUST implement a structured API endpoint at `GET /api/health` that returns a JSON object containing the current health status of all infrastructure components.

- **Contract**:
  - Endpoint: `GET /api/health`
  - Response Format (JSON):
    ```json
    {
      "database": "healthy" | "unhealthy",
      "runtime": "healthy" | "unhealthy",
      "tests": "healthy" | "unhealthy",
      "src": "healthy" | "unhealthy"
    }
    ```
  - Response Code: `200 OK` (if connectivity established), `500 Internal Server Error` (only if the request processing fails unexpectedly).

### FR-DASHBOARD_UI_INIT
The system MUST implement a dashboard page at `/health` that renders the current infrastructure health status using visual indicators (e.g., green/red status icons).

- **Contract**:
  - Path: `/health`
  - UI: Component structure that fetches health data and updates visual status indicators.

### FR-DASHBOARD_DATA_BINDING
The dashboard UI MUST fetch data from the `GET /api/health` endpoint upon page load and display the status for each infrastructure component.

- **Contract**:
  - UI interaction: Asynchronous data fetch from the status API.

## Interface Boundaries

- **Entry Boundary (API)**:
  - `GET /api/health`
  - Input: None.
  - Output: Structured JSON health status.
- **Entry Boundary (Web Interface)**:
  - `GET /health`
  - Output: Dashboard HTML/UI component.
- **Dependency Boundary**:
  - Backend: `src/autonomedia/checks/healthcheck.py` (Asynchronous status data provider).

## Implementation Tasks

1.  Create API endpoint handler (`src/autonomedia/web/api/health.py`) using `healthcheck.py` results [FR-STATUS_ENDPOINT_INIT].
2.  Implement `GET /api/health` handler logic [FR-STATUS_ENDPOINT_INIT].
3.  Register API route in the web router (`src/autonomedia/web/router.py`) [FR-STATUS_ENDPOINT_INIT].
4.  Create Dashboard UI component (`src/autonomedia/web/ui/dashboard/health.jsx`) [FR-DASHBOARD_UI_INIT].
5.  Implement data fetching and binding logic in the Dashboard UI [FR-DASHBOARD_DATA_BINDING].
6.  Update Autonomedia web router for `/health` path [FR-DASHBOARD_UI_INIT].

## Constraints & Assumptions

- The implementation relies on the established `healthcheck.py` utility.
- Authentication/access control for `/health` and `/api/health` is out of scope for this spec (default public or existing web-app auth applies).
- Dashboard data fetching relies on asynchronous requests.

## Acceptance Criteria

- `FR-STATUS_ENDPOINT_INIT` verified: `GET /api/health` returns JSON with keys (database, runtime, tests, src) and expected values.
- `FR-DASHBOARD_UI_INIT` verified: `/health` page renders the dashboard UI component.
- `FR-DASHBOARD_DATA_BINDING` verified: Dashboard displays the current health status corresponding to the `/api/health` JSON.
