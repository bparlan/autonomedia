Create the deterministic verification protocol for the Infrastructure Data Endpoint (SPEC-M18S2) that will guide the generation of executable tests. The verification covers both the API endpoint contract and dashboard integration.

## Initial Failure Expectations

The following test conditions represent valid initial failures when the implementation is incomplete:

1. **Server Not Running**: Exit code 127 (command not found) when attempting server startup
2. **Module Import Errors**: Exit code 1 when backend modules are missing or have syntax errors
3. **Invalid Input Data**: Exit code 1 when input validation fails
4. **Network Connectivity**: Exit code 127 when dependencies are unavailable

## Integration Readiness Gates

### Testable Components

1. **Endpoint Accessibility**: 
   - HTTP GET `/api/health` must return 200 OK
   - Response must contain valid JSON with all required status keys

2. **Data Validation**:
   - JSON must contain all four status keys: `database`, `runtime`, `tests`, `src`
   - Each value must be either `"healthy"` or `"unhealthy"`
   - Response must validate against defined JSON schema

3. **Integration Functionality**:
   - Backend functions must return status dictionary correctly
   - Frontend `/health` page must successfully fetch and parse the endpoint response

## Test Execution Constraints

- Only script-based tests (`.sh`) are permitted for process monitoring
- Only shell script commands that can be executed in CI environment may be used
- No custom executable binaries may be referenced
- All PATH resolution follows Linux `$PATH` rules
