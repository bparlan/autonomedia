## Objective

Define comprehensive platform-specific requirements for LinkedIn, X (Twitter), and Mastodon, including character limits, field limits, formatting rules, content adaptation strategy, anti-detection requirements, and platform-specific constraints. Document implementation guidelines to ensure cross-platform publishing consistency and compliance.

---

## Functional Requirements

### Platform Character Limits

**FR1.1**: LinkedIn platform character limits:
- Title: maximum 300 characters, no trailing period
- Summary: maximum 3,000 characters
- Tags: maximum 5 tags, each maximum 25 characters
- Total post: title + summary + tags combined must not exceed 3,300 characters

**FR1.2**: X (Twitter) platform character limits:
- Standard tweet: maximum 280 characters
- Thread starter: maximum 100 characters for first tweet in thread
- Thread continuation: maximum 100 characters for subsequent tweets
- Hashtags: maximum 3 hashtags per post
- Article link: link must be included at end of post if article content exceeds limits

**FR1.3**: Mastodon platform character limits:
- Toot: maximum 500 characters
- Status: maximum 500 characters
- Note: maximum 500 characters
- Hashtags: unlimited, but recommended maximum 3-5 for readability
- Links: unlimited in toot, no character limit for URLs

## Platform-Specific Requirements

### LinkedIn Platform Requirements

**FR2.1**: Content Structure:
- LinkedIn requires three distinct fields: title, summary, and tags
- Title must be extracted from first 200 characters of content (with max cap of 300)
- Summary must contain remaining content after title extraction
- Article link must be preserved and appended to the end of the post
- Post must use markdown or plain text formatting compatible with LinkedIn

**FR2.2**: Formatting Rules:
- Title: strictly no trailing period (LinkedIn removes periods from titles)
- Summary: may include paragraph breaks (line breaks) for readability
- Tags: comma-separated string, no trailing comma
- Tags: no duplicate tags within same post
- Article link format: must be valid URL (http/https), linked from text or appended at end
- Professional tone required (business-appropriate language, formal yet engaging)

**FR2.3**: Anti-Detection Requirements:
- Randomized delays between posts (5-10 seconds recommended)
- Human-like scrolling behavior during posting
- Randomized viewport sizes (1920x1080, 1366x768, 1536x864)
- User agent spoofing to avoid detection
- No rapid-fire consecutive posts from same account
- Smooth, natural typing speed (not instant)
- Prevent detection by LinkedIn's automated systems

**FR2.4**: Rate Limiting:
- Implement exponential backoff for rate limit errors (429 status codes)
- Maximum 3 retry attempts with increasing delays (2s, 4s, 8s base intervals)
- Respect LinkedIn API rate limits (1 post per 5 minutes per connection recommended)
- Monitor for account restrictions or posting throttling
- Log rate limit events with timestamps and platform-specific details

**FR2.5**: Authentication Requirements:
- OAuth 2.0 flow required for LinkedIn authentication
- Tokens must be stored securely (environment variables or encrypted vault)
- Token expiration detection and automatic refresh capability
- Session health validation before each post
- Support for multiple LinkedIn connections (if applicable)
- Clear error messaging for authentication failures (401 Unauthorized, 403 Forbidden)

### X (Twitter) Platform Requirements

**FR3.1**: Content Formatting:
- X requires single unified tweet format (not thread by default)
- Post must be exactly 280 characters or less
- If content exceeds 280 characters, truncate with ellipsis at cutoff point
- Preserve article link at end of post regardless of truncation
- No trailing spaces after link
- Link must be immediately after content, no extra spacing

**FR3.2**: Hashtag Formatting:
- All hashtags must start with # symbol
- First letter of each hashtag must be capitalized (camelCase)
- No leading # on first word (only on hashtag terms)
- Max 3 hashtags per post
- Hashtags must be spaced from text (space between hashtag and adjacent text)
- Remove duplicate hashtags if multiple exist in content

**FR3.3**: Strong Hook Requirement:
- First line must contain the strongest, most engaging content
- Hook should be informative or controversial to drive engagement
- Hook must be preserved during truncation (not cut off mid-word)
- If hook cut off, move hook to start of new tweet in thread format

**FR3.4**: Article Link Handling:
- Article link must always be included in X post
- Link format: https://domain.com/article (no trailing slash unless intended)
- Link must be last element in post (after all content and hashtags)
- Link length reduces available character space
- Use shortened URLs if original link exceeds limit

**FR3.5**: Anti-Detection Requirements:
- Randomized delays between posts (5-10 seconds between batches)
- Randomized delays within batch (1-3 seconds between individual posts)
- Randomized viewport sizes (2560x1440, 1920x1080, 1366x768)
- User agent spoofing matching real browser versions
- No identical timing patterns between posts
- Smooth scrolling and form interactions
- Prevent detection by X's automated systems

**FR3.6**: Rate Limiting:
- Implement exponential backoff for rate limit errors (429 status codes)
- Maximum 3 retry attempts with increasing delays (2s, 4s, 8s base intervals)
- Respect X API rate limits (limited free tier, higher limits for paid accounts)
- Monitor for rate limit warnings (early detection)
- Log rate limit events with timestamps and context
- Support for batch posting with controlled delays (max 5 seconds per batch for success)

**FR3.7**: Authentication Requirements:
- OAuth 2.0 flow required for X authentication
- Tokens must be stored securely (environment variables or encrypted vault)
- Token expiration detection and automatic refresh capability
- Session health validation before each post
- Support for multiple X connections (if applicable)
- Clear error messaging for authentication failures (401 Unauthorized, 403 Forbidden)

### Mastodon Platform Requirements

**FR4.1**: Content Structure:
- Mastodon uses unified "toot" format with optional title and body
- Title (max 200 chars) optional, must be followed by separator
- Body contains main content
- Hashtags optional but recommended
- Article link optional but recommended

**FR4.2**: Formatting Rules:
- Use plain text (markdown is not widely supported)
- Title must be separated from body with "---" separator
- Hashtags must start with # symbol
- Hashtags should be lowercase or title case consistently
- No hashtags at start of message
- Article link at end if present
- Use line breaks for paragraph separation (double newline)
- Maximum 500 characters total

**FR4.3**: Anti-Detection Requirements:
- Randomized delays between posts (3-8 seconds)
- Randomized viewport sizes (1280x720, 1920x1080, 2560x1440)
- User agent spoofing matching Mastodon instance or common browser
- No rapid-fire posting (consistent timing patterns)
- Smooth form interactions
- Prevent detection by Mastodon's automated systems (less strict than LinkedIn/X)

**FR4.4**: Rate Limiting:
- Implement exponential backoff for rate limit errors (429 status codes)
- Maximum 3 retry attempts with increasing delays (2s, 4s, 8s base intervals)
- Respect Mastodon API rate limits (1 request per 2 minutes for authentication)
- Monitor for server-side throttling
- Log rate limit events with timestamps

**FR4.5**: Authentication Requirements:
- OAuth 2.0 flow required for Mastodon authentication
- Tokens must be stored securely (environment variables or encrypted vault)
- Token expiration detection and automatic refresh capability
- Session health validation before each post
- Support for multiple Mastodon instances (if applicable)
- Clear error messaging for authentication failures

## Content Adaptation Strategy

**FR5.1**: Text Length Adaptation:
- LinkedIn: Extract title (max 300) and summary (max 3000) from content
- X: Truncate to 280 characters, preserve hook and link
- Mastodon: Keep as-is if ≤500 chars, truncate with ellipsis if longer

**FR5.2**: Tone Adaptation:
- LinkedIn: Professional, informative, business-appropriate tone
- X: Punchy, engaging, opinionated or informative hook
- Mastodon: Neutral, informative, community-focused tone

**FR5.3**: Hashtag Adaptation:
- LinkedIn: Extract existing tags, limit to 5, max 25 chars each
- X: Extract hashtags, capitalize first letter, max 3 per post, ensure no duplicates
- Mastodon: Extract hashtags, lowercase for consistency, recommended max 5

**FR5.4**: Link Preservation:
- All platforms must preserve article link
- Link must be last element in post (after all content)
- Link format validated (http/https scheme)
- Use shortened URLs if original link exceeds character limits

**FR5.5**: Cross-Platform Uniqueness:
- Content MUST be adapted differently per platform
- NO identical text across LinkedIn, X, and Mastodon
- Use different hooks, hashtags, or formatting for each platform
- Minimum 10% difference in content structure between platforms

## Anti-Detection Requirements

**FR6.1**: Browser Profile Configuration:
- Headless mode DISABLED (visible browser automation)
- Randomized viewport sizes per platform and per session
- User agent spoofing with realistic browser versions
- Disable automated detection signals (Windows Automation API, etc.)
- Use browser profiles with unique cookies/localStorage

**FR6.2**: Behavioral Anti-Detection:
- Randomized delays between actions (scroll, type, click)
- Human-like typing speed (not instant, not robotic)
- Randomized mouse movement during scrolling
- No rapid-fire consecutive clicks
- Wait for page load and animations before interaction
- Respect page transitions and loading states

**FR6.3**: Platform-Specific Anti-Detection:
- LinkedIn: Avoid posting too frequently (max 1 post per 5 minutes per account)
- X: Vary posting times (not always same time of day), avoid identical content
- Mastodon: Lower frequency threshold (max 1 post per 10 minutes per instance)
- Avoid posting identical content on multiple platforms simultaneously
- Rotate posting times across days

**FR6.4**: Network Anti-Detection:
- Use residential IP addresses where possible
- Rotate IP addresses for multiple accounts
- Avoid obvious patterns (always same time, same duration)
- Randomize network request timing
- Use realistic user agent + IP correlation

**FR6.5**: Content Anti-Detection:
- Vary post structure and formatting per platform
- Different hashtags and hooks per platform
- Different posting times for identical content
- Avoid identical content posted within short timeframe (hours)
- Mix content types (opinion, news, articles, personal updates)

## Platform-Specific Constraints

**FR7.1**: No Identical Cross-Posting:
- The system MUST NOT post identical content across LinkedIn, X, and Mastodon
- Content must be adapted with minimum 10% difference
- Platform-specific fields (title, summary, tags) must differ
- Hashtag strategy must differ (same tag? different tags)
- Link handling must differ (some platforms require link, others optional)

**FR7.2**: LinkedIn-Specific Constraints:
- Cannot post content without title (title is required field)
- Title cannot be empty (minimum 10 characters recommended)
- Tags must be comma-separated, no duplicates
- Summary must follow title (format: "Title\n\nSummary\n\nTags")
- Professional tone mandatory
- No emojis or informal language (unless contextual)

**FR7.3**: X (Twitter)-Specific Constraints:
- Cannot post content >280 characters (must truncate)
- Cannot post more than 3 hashtags (enforced)
- Hashtags must be camelCase (first letter capitalized)
- Hook must be preserved (cannot cut off at end)
- Link must be at end of post (no link before hashtags)
- Thread creation requires separate handling (not default behavior)

**FR7.4**: Mastodon-Specific Constraints:
- No markdown support (plain text only)
- Title optional (if not used, no separator)
- Hashtags optional (recommended but not required)
- Link at end if present
- No maximum hashtag count (but recommended ≤5 for readability)
- Content must be exactly 500 chars or less (enforced)

**FR7.5**: Rate Limit Constraints:
- LinkedIn: max 1 post per 5 minutes per account
- X: depends on API tier (free: limited, paid: higher limits)
- Mastodon: max 1 post per 2 minutes per account (free tier)
- Batching must respect platform-specific rate limits
- Automatic backoff for rate limit errors
- Warning system for approaching rate limits

## Non-Functional Requirements

### Security

**NFR1.1**: Authentication tokens must be stored securely (environment variables or encrypted vault)
**NFR1.2**: No hardcoded tokens or credentials in source code
**NFR1.3**: Token refresh must be handled securely without exposing credentials
**NFR1.4**: Session cookies must be stored securely and rotated periodically
**NFR1.5**: API keys and secrets must never be logged or exposed in error messages

### Reliability

**NFR2.1**: Exponential backoff must be implemented for all platforms (2s, 4s, 8s delays)
**NFR2.2**: Retry logic must support maximum 3 attempts for transient failures
**NFR2.3**: Rate limit detection must be accurate (429 status codes)
**NFR2.4**: Authentication failures must trigger manual intervention flow
**NFR2.5**: Batch posting must handle failures without stopping entire batch
**NFR2.6**: All errors must be logged with timestamps and context

### Maintainability

**NFR3.1**: Platform handlers must be modular and self-contained
**NFR3.2**: Platform-specific logic must be clearly separated from shared logic
**NFR3.3**: Anti-detection techniques must be configurable (delay ranges, viewport sizes)
**NFR3.4**: Rate limit configuration must be centralized and easily adjustable
**NFR3.5**: Documentation must be comprehensive and include examples for each platform

### Performance

**NFR4.1**: X handler batch posting must complete within 5 seconds per batch
**NFR4.2**: Content normalization must complete within 100ms
**NFR4.3**: Delay delays between posts must not cause excessive delays
**NFR4.4**: Batch processing must handle all posts within reasonable time (not indefinite)
**NFR4.5**: Memory usage must be optimized (no memory leaks in handlers)

### Usability

**NFR5.1**: Platform selection must be simple and intuitive
**NFR5.2**: Error messages must be clear and actionable
**NFR5.3**: Success indicators must be prominent (checkmarks, green badges)
**NFR5.4**: Rate limit warnings must be visible and timely
**NFR5.5**: Batch progress must be visible during posting

## Data Flow

1. **Content Ingestion**: User or AI generates content with platform target
2. **Platform Selection**: System identifies which platforms to post to
3. **Content Validation**: Validate content against platform constraints (character limits, formatting)
4. **Content Adaptation**: Adapt content per platform (text length, tone, hashtags)
5. **Authentication**: Platform-specific handler retrieves credentials from secure storage
6. **Anti-Detection Setup**: Configure browser profile with randomized settings
7. **Posting**: Handler executes posting with platform-specific logic
8. **Response Capture**: Handler returns success/failure status and post ID
9. **Status Update**: Assembly Line updates content status to `published` or records failure

**Data Structures**:
- `content: str`: Original content to post
- `options: dict`: `{platform: str, content_id: str, article_link: str, ...}`
- `validated_content: dict`: `{platform: str, title: str, body: str, tags: list, formatted: str}`
- `PlatformConstraints: dict`: Platform-specific limits and rules
- `PlatformResponse: dict`: `{success: bool, platform: str, post_id: str, error: str, ...}`

## Constraints

- **Technology Stack**: Must use Playwright for browser automation, existing Python stack
- **Platform Limits**: Only LinkedIn, X, and Mastodon supported (no Instagram, TikTok, etc.)
- **Content Adaptation**: Content MUST be adapted per platform; no identical cross-posting (minimum 10% difference)
- **Authentication**: Each platform requires separate OAuth 2.0 flow; no shared authentication
- **Anti-Detection**: Browser profiles must remain anti-detection-compliant; no visual content generation
- **Rate Limits**: Must implement exponential backoff and monitoring for all platforms
- **Platform APIs**: APIs change frequently; require monitoring and easy reauthentication
- **Output Format**: LinkedIn requires title + summary + tags; X requires <280 chars; Mastodon requires ≤500 chars
- **Character Limits**: Strict enforcement of all platform character limits
- **No Cross-Posting**: No identical content across platforms within short timeframe
