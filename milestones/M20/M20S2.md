# Specification: M20S2 - Integration Binding Validation Across All Layers

## Objective

Implement automated integration binding validation across all layers of Autonomedia's 3-layer architecture (Core Infrastructure, AI Engine, Platform Adapters, Web Application, Data Registries). This specification validates that all cross-layer dependencies maintain proper layer boundaries and isolation constraints while ensuring system integrity.

## Followup Context

M20S2 builds upon M20S1's directory structure auditing by validating the actual integration points between all architectural layers. It ensures that the enforced layer boundaries are respected in practice, not just structurally.

## Functional Requirements

### FR-INTEGRITY_CORE_AI_BINDING
- **Type**: CLI Executable Contract
- **Interface Contract**: `uv run python scripts/checks/integrity_core_ai.py --validate --output storage/data/integration_core_ai_binding.json`
- **Expected Behavior**: Validates Core Infrastructure ↔ AI Engine integration boundaries by scanning for cross-imports and runtime dependencies between `src/autonomedia/core/` and `src/autonomedia/ai/rewriting/` modules.
- **Observable Boundary**: Exit code 0 when all core-AI integrations valid; exit code 2 when cross-layer imports detected; exit code 3 when analysis fails. Generates `storage/data/integration_core_ai_binding.json` containing validated bindings array.
- **Allowed Files**: `scripts/checks/integrity_core_ai.py`
- **Affected Modules**: `scripts/checks/integrity_core_ai.py`
- **New Modules**: `scripts/checks/integrity_core_ai.py` with `validate_core_ai_integrity()` and `analyze_integration_bindings()` exports

### FR-INTEGRITY_PLATFORM_CORE_BINDING
- **Type**: CLI Executable Contract
- **Interface Contract**: `uv run python scripts/checks/integrity_platform_core.py --validate --output storage/data/integration_platform_core_binding.json`
- **Expected Behavior**: Validates Core Infrastructure ↔ Platform Adapters integration boundaries, ensuring platform handlers maintain isolation and don't access core infrastructure APIs improperly.
- **Observable Boundary**: Exit code 0 when all platform-core integrations valid; exit code 2 when platform-core violations detected; exit code 3 when analysis fails. Generates `storage/data/integration_platform_core_binding.json`.
- **Allowed Files**: `scripts/checks/integrity_platform_core.py`
- **Affected Modules**: `scripts/checks/integrity_platform_core.py`
- **New Modules**: `scripts/checks/integrity_platform_core.py` with `validate_platform_core_integrity()` and `check_isolation_violations()` exports

### FR-INTEGRITY_WEB_DATA_BINDING
- **Type**: CLI Executable Contract
- **Interface Contract**: `uv run python scripts/checks/integrity_web_data.py --validate --output storage/data/integration_web_data_binding.json`
- **Expected Behavior**: Validates Web Application ↔ Data Registry integration boundaries, ensuring web templates can access required data registries while maintaining immutability constraints.
- **Observable Boundary**: Exit code 0 when all web-data integrations valid; exit code 2 when web-data violations detected; exit code 3 when analysis fails. Generates `storage/data/integration_web_data_binding.json`.
- **Allowed Files**: `scripts/checks/integrity_web_data.py`
- **Affected Modules**: `scripts/checks/integrity_web_data.py`
- **New Modules**: `scripts/checks/integrity_web_data.py` with `validate_web_data_integrity()` and `check_registry_access()` exports

### FR-INTEGRITY_PLATFORM_ISOLATION
- **Type**: Structured Schema Contract
- **Interface Contract**: `storage/data/platform_isolation_report.json` with defined schema for platform isolation validation
- **Expected Behavior**: Validates that all platform adapters remain isolated - no cross-platform imports, no shared browser profiles, no cross-platform dependencies.
- **Observable Boundary**: Generates `storage/data/platform_isolation_report.json` containing `isolated_platforms` array and `cross_platform_violations` array. Exit code 0 if no violations; exit code 2 if violations found.
- **Allowed Files**: `scripts/checks/integrity_platform_isolation.py`
- **Affected Modules**: `scripts/checks/integrity_platform_isolation.py`
- **New Modules**: `scripts/checks/integrity_platform_isolation.py` with `validate_platform_isolation()` and `detect_cross_platform_imports()` exports

### FR-INTEGRITY_RUNTIME_DETERMINISM
- **Type**: CLI Executable Contract
- **Interface Contract**: `uv run python scripts/checks/integrity_runtime_determinism.py --validate --compare storage/data/integration_binding_matrix_1.json storage/data/integration_binding_matrix_2.json`
- **Expected Behavior**: Validates that integration binding validation produces deterministic results across multiple runs by comparing SHA-256 checksums of generated integration matrices.
- **Observable Boundary**: Exit code 0 when checksums match 100%; exit code 1 when checksums differ; exit code 2 when validation fails. Reports deterministic compliance status.
- **Allowed Files**: `scripts/checks/integrity_runtime_determinism.py`
- **Affected Modules**: `scripts/checks/integrity_runtime_determinism.py`
- **New Modules**: `scripts/checks/integrity_runtime_determinism.py` with `validate_deterministic_integrity()` and `compare_integration_matrices()` exports

## Interface Boundaries

### Module Entry/Exit Contracts

#### Core-AI Integration Validation
- **Entry**: `validate_core_ai_integrity(repo_root: str) -> dict`
  - Input: Repository root path
  - Processing: AST-based import analysis between core and AI modules
  - Output: Integration validation results with `validated_bindings` and `violations` arrays
- **Exit**: Generates `integration_core_ai_binding.json` with validated bindings
- **Environment Variables**: `REPO_ROOT` (defaults to `.`)

#### Platform-Core Integration Validation
- **Entry**: `validate_platform_core_integrity(repo_root: str) -> dict`
  - Input: Repository root path
  - Processing: Static analysis of platform adapter imports to core infrastructure
  - Output: Isolation validation results with `isolated_platforms` and `violations` arrays
- **Exit**: Generates `integration_platform_core_binding.json` with isolation reports
- **Environment Variables**: `REPO_ROOT` (defaults to `.`)

#### Web-Data Integration Validation
- **Entry**: `validate_web_data_integrity(repo_root: str) -> dict`
  - Input: Repository root path
  - Processing: Validation of web template access to data registries
  - Output: Integration validation results with `valid_access` and `registry_violations` arrays
- **Exit**: Generates `integration_web_data_binding.json` with web-data integration reports
- **Environment Variables**: `REPO_ROOT` (defaults to `.`)

#### Platform Isolation Validation
- **Entry**: `validate_platform_isolation(repo_root: str) -> dict`
  - Input: Repository root path
  - Processing: Detection of cross-platform imports and shared dependencies
  - Output: Isolation validation results with `fully_isolated_platforms` and `cross_platform_violations` arrays
- **Exit**: Generates `platform_isolation_report.json` with isolation status
- **Environment Variables**: `REPO_ROOT` (defaults to `.`)

#### Runtime Determinism Validation
- **Entry**: `validate_deterministic_integrity() -> dict`
  - Input: None (reads from filesystem)
  - Processing: Runs integration validation twice and compares outputs
  - Output: Determinism validation results with `checksum_match` and `comparison_details`
- **Exit**: Compares `integration_binding_matrix_1.json` and `integration_binding_matrix_2.json`
- **Environment Variables**: `STORAGE_PATH` (defaults to `storage/data/`)

*   Web templates are located in `src/web/templates/` serving FastAPI routes.
