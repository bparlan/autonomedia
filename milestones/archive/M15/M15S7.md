| Scope         | Fix Dashboard Bugs: Approve Button Logic, Registry Path, Platform Health Display |

## Objective

Fix three critical bugs discovered in M15S6 implementation:
1. Approve button logic mismatch preventing idea → approved transition
2. Registry file path incorrect causing 404 errors
3. Platform health field mapping missing causing empty display

---

## Functional Requirements

### FR7.1: Fix Approve Button Status Transition

**FR7.1.1**: The `/approve-idea/{item_id}` route handler shall accept items with status='idea'.
- Change status validation from `approved` to `idea`
- Transition status from `idea` to `approved`
- Return HTTP 400 if item has any other status

**FR7.1.2**: The approve_idea handler shall update database with correct status transition.
- `SELECT` item with matching id
- `UPDATE` status to 'approved'
- `RETURN` 303 redirect to /content

### FR7.2: Fix Registry File Path

**FR7.2.1**: The `/registry` route handler shall locate the registry file correctly.
- Use `Path(__file__).parent.parent` (not `.parent.parent.parent`)
- Navigate to `src/autonomedia/content/mention_registry.json`
- Return 404 only if file genuinely does not exist

### FR7.3: Fix Platform Health Display

**FR7.3.1**: The `/platforms` route handler shall map `is_healthy` to `status` field.
- Query `platform_health` table for `platform_name` and `is_healthy`
- Transform `is_healthy` boolean to "healthy"/"unhealthy" string
- Pass mapped data to `platforms.html` template

---

## Non-Functional Requirements

### NFR7.1: Data Consistency
- Status transitions must be atomic
- No regression on existing functionality

### NFR7.2: Error Handling
- Non-existent items return 404
- Invalid status returns 400 with clear message
- Missing registry file returns 404 with message
