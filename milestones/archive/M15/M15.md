## Goal

Entire application should be suitable to be used as multi-platform. Additional platform adding must be possible with no issues.

---

## Motivation

For every post, user will be able to keep a social media platform active, utilized as a tool for idea to spread and known for the long term. User will focus in ideas and content, and Autonomedia app will deal with platforms for distribution.

---

## Scope

- **LinkedIn task handler deployed and tested** — Handler processes LinkedIn-ready content with correct posting format, proper character limits, and LinkedIn-specific fields (title, summary, tags).
- **X (Twitter) task handler deployed and tested** — Handler posts content under 280 characters (or threads as appropriate) with correct hashtag handling and tone.
- **Unified platform abstraction layer with API for posting** — Common interface that abstracts Mastodon, LinkedIn, and X behind identical `post(content, options)` API.
- **Platform-specific requirements documented** — Documented for all three platforms including:
  - Character limits and field requirements
  - Rate limits and backoff strategies
  - Authentication requirements and session management
  - Platform-specific content sharing advice (LinkedIn: professional tone, 2-4 sentences; X: short/punchy, <280 chars; Mastodon: current behavior)
  - Platform culture and tone guidelines

---

## Out of Scope

- Other platforms beyond LinkedIn, X, and Mastodon (no Instagram, TikTok, Threads, Bluesky, Farcaster, etc.)
- No visual content generation (images, video)
- No video content
- No cross-posting the exact same text across all platforms (content must be adapted per platform)

---

## Success Criteria

 - [ ] LinkedIn handler processes 100% of LinkedIn-ready content without errors
 - [ ] X handler posts under 5 seconds per batch
 - [ ] Unified platform API successfully handles Mastodon, LinkedIn, X with identical interface
 - [ ] Platform-specific requirements documented for all three platforms
 - [ ] All three verification protocols (M15S2V, M15S3V, M15S4V) pass

---

## Risks

- **Platform-specific rate limits could cause delivery failures** — Each platform has different rate limits; need exponential backoff and monitoring.
- **Each platform session and authentication may vary** — Mastodon uses API tokens; LinkedIn and X may require OAuth 2.0 or different auth flows; session management must be flexible.
- **Extremely cautious about AI detection; humanlike time consumption during browser and posting is critical** — Browser profiles must remain anti-detection-compliant across all platforms; randomized delays and pacing must match each platform's cultural norms.

---

## Notes

- **Platform APIs change frequently** — Require monitoring and easy "reauthentication" from platform management panel; authentication tokens should be stored securely and accessible for refresh.
- **Platform authentication may not directly translate to other platforms** — Each platform needs separate authentication setup; abstraction layer must handle different auth flows transparently.
- **Browser profiles must remain anti-detection-compliant** — All platforms must use Playwright anti-detection profiles; timing and behavior must be consistent with human-like posting patterns.
