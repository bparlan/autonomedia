## Root Cause Analysis

### Issue 1: Approve Button Causes Page Loop

**Location**: `src/web/app.py:479` and `src/web/templates/partials/content_row.html:62`

The `/approve-idea/{item_id}` route returns a **303 redirect** after successful approval:
```python
return RedirectResponse(url="/content", status_code=303)
```

However, the template uses HTMX:
```jinja2
<button hx-post="/approve-idea/{{ item.id }}" hx-target="#row-{{ item.id }}" hx-swap="outerHTML">
```

**Root Cause**: HTMX expects HTML fragment to replace the target element, but receives a redirect response. The `hx-swap="outerHTML"` causes the redirect response to replace the `<tr>` element's outer HTML, which includes the full page content instead of just the updated row.

### Issue 2: "Generating" Status Appears Without Action

**Location**: `src/web/templates/partials/content_row.html:26` and `src/web/app.py:377-381`

The status cell has automatic polling:
```jinja2
{% if item.status in ['approved', 'rewriting'] %}hx-get="/status-fragment/{{ item.id }}" hx-trigger="every 5s"{% endif %}
```

The `/status-fragment/{item_id}` endpoint returns hardcoded inline HTML:
```python
status_html = "<td class='p-4 align-top'>...Generating...</span></td>"
```

**Root Cause**: 
- Automatic HTMX polling every 5 seconds triggers status updates
- `status_fragment()` returns static "Generating" HTML regardless of actual item status
- No query to check real status, just returns hardcoded "Generating"

### Issue 3: "Generate Rewrites" Button Redirects Entire Page

**Location**: `src/web/templates/rewrites.html:14`

```jinja2
<button hx-post="/batch-generate" hx-target="body" class="...">Generate Rewrites</button>
```

**Root Cause**: `hx-target="body"` targets the entire document body. When `/batch-generate` returns 303 redirect, HTMX replaces the entire body with the redirect response, causing page navigation but without proper page transition.

### Issue 4: Platform Status Missing Management Features

**Location**: `src/web/templates/platforms.html`

Template only displays:
```jinja2
{% for h in platform_health %}
    <span class="font-bold capitalize text-gray-900 dark:text-white">{{ h.platform_name }}</span>
    <span class="{% if h.status == 'healthy' %}text-green-600{% else %}text-red-600{% endif %}">
        {{ h.status | capitalize }}
    </span>
    <button class="...">Connect</button>
{% endfor %}
```

**Root Cause**: Platforms page is read-only display. No:
- Re-authentication flow
- Add platform functionality
- Platform connection status management
- Authentication token status checking
