## Root Cause Analysis

**Issue**: All menu buttons in the web app (except Command Center) return 404 Not Found because `src/web/app.py` is a minimal stub with only 2 endpoints (`/` and `/health`). The original implementation (commit ef06942) had 18+ missing route handlers that are required for the application to function.

**Specific Location**: `src/web/app.py` currently only contains:
- `GET /` - Dashboard page (minimal stub)
- `GET /health` - Health check endpoint (minimal stub)

**Evidence**:
1. Template files reference multiple routes via `<a href="/content">`, `<a href="/rewrites">`, `<a href="/registry">`, `<a href="/platforms">`, `<form action="/add" method="POST">`, `<form action="/registry/update" method="POST">`, `<form action="/review/{{ item.id }}/approve" method="POST">`, etc.
2. `grep` of `src/web/templates` shows 15+ unique route references that are not currently implemented
3. M15I1 investigation report (4.7K) identified this as the root cause of menu button 404 errors
4. M15S5 specification FR3.1 requires all 18+ missing route handlers to be implemented

## Architecture Assessment

### Regression Risk: **HIGH**

**Risk Factors**:
1. **Database Schema Unknown**: Cannot verify if `content` table and `platform_health` table exist with required columns
2. **Existing Integration Unknown**: No evidence of existing database integration in web app codebase
3. **Template Dependencies**: Templates reference database queries and partials that may not exist
4. **Form Validation Unknown**: FastAPI Form parameter binding behavior not tested

**Potential Breaking Changes**:
- Adding route handlers may conflict with existing handler signatures
- DatabaseClient usage pattern may not match existing codebase conventions
- Jinja2 filter definitions may need updates

### Architectural Constraint Violations

1. **FR3.2 Violation** (Current): Routes do not integrate with DatabaseClient
   - **Impact**: Cannot query database for content, platform health, or registry
   - **Required Fix**: Add `DatabaseClient.get_pool()` to all routes

2. **FR3.3 Violation** (Current): Templates may not use Environment loader correctly
   - **Impact**: Starlette caching issues, template rendering errors
   - **Required Fix**: Use `Environment(loader=FileSystemLoader(...))` instead of TemplateResponse

3. **FR3.4 Violation** (Current): No empty database state handling
   - **Impact**: Database errors or crashes when tables are empty
   - **Required Fix**: Add graceful error handling for missing tables and empty results

### Design Pattern Breaks

1. **Async Database Access**: Existing code may use sync DB access (syncpg) instead of asyncpg
   - **Impact**: Route handlers using DatabaseClient will fail if DB code is sync
   - **Required Fix**: Verify all DB operations are async

2. **Template Loading Pattern**: Existing code may use TemplateResponse (Starlette's default)
   - **Impact**: Caching issues, template loading errors
   - **Required Fix**: Use Environment(loader=FileSystemLoader(...)) pattern

3. **Error Handling**: Existing code may not have try/except blocks for DB errors
   - **Impact**: Unhandled exceptions crash entire application
   - **Required Fix**: Add comprehensive error handling for all routes
