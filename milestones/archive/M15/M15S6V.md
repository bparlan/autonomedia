## Success Criteria

### Content Management Routes

- [ ] `GET /content` returns valid HTML with database items or "No content available" message
- [ ] `POST /add` successfully creates content in database
- [ ] `POST /add` redirects to `/content` after successful creation
- [ ] `DELETE /delete-item/{id}` removes item from database
- [ ] `GET /edit-content-row/{id}` renders edit form
- [ ] `POST /save-content-row/{id}` updates database
- [ ] `GET /cancel-edit-content/{id}` renders edit form with original values
- [ ] `GET /prepared-content/{id}` returns prepared content preview
- [ ] `GET /status-fragment/{id}` returns status HTML fragment

### Review Workflow Routes

- [ ] `GET /review/{id}` returns 400 if status is not 'prepared'
- [ ] `GET /review/{id}` displays prepared content when status is 'prepared'
- [ ] `POST /review/{id}/approve` validates status is 'prepared'

- [ ] `POST /approve-idea/{id}` updates status to 'approved'
- [ ] `POST /reset-failure/{id}` resets status to 'approved'
- [ ] `POST /remove-from-queue/{id}` resets status to 'approved'

### Platform Management Routes

- [ ] `GET /platforms` queries platform_health table

### Security

## Failure Scenarios

### Database Connection Failures

**NFR6.2 / FR6.22**: Database connection timeout or failure
- **Trigger**: Stop PostgreSQL service, reload http://localhost:8000/content
- **Expected**: HTTP 500 with user-friendly message, error logged in console
- **Detection**: Check server logs, check HTTP response code and message

### SQL Injection Attempts

**NFR6.4**: Malicious SQL in form inputs
- **Trigger**: Submit topic with value `"'; DROP TABLE content; --"`
- **Expected**: Parameterized query prevents injection, record created with malicious string as topic value
- **Detection**: Verify database integrity, verify content table unchanged

### Missing Database Tables

**FR6.23**: Query non-existent table
- **Trigger**: Drop content table, access `/content`
- **Expected**: HTTP 404 with "No content available" message
- **Detection**: Check HTTP response, verify graceful handling

### Invalid Form Data

**NFR6.5**: Multiple invalid form submissions
- **Trigger**: Submit form with all invalid fields simultaneously
- **Expected**: All validation errors returned, no database changes
- **Detection**: HTTP 400 response, database unchanged

### File System Failures

**FR6.26/FR6.27**: File permission denied
- **Trigger**: Set registry file to read-only, attempt save
- **Expected**: HTTP 500 with error, file unchanged
- **Detection**: HTTP 500 response, check error message

### Path Traversal Attempts

**Security**: Attempt to access files outside web app
- **Trigger**: Attempt to access `/registry/../../../etc/passwd`
- **Expected**: Route not implemented, 404 returned
- **Detection**: HTTP 404, no file access
