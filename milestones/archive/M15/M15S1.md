## Objective

Enable multi-platform autonomous publishing by creating a unified platform abstraction layer that abstracts Mastodon, LinkedIn, and X behind identical APIs, and deploy task handlers for LinkedIn and X with platform-specific requirements, authentication, and anti-detection compliance.

---

## Functional Requirements

### Platform Abstraction Layer

**FR1.1**: The system shall provide a unified `post(content, options)` API that abstracts all platform-specific posting logic behind a common interface, accepting `content` (string) and `options` (dict) parameters.

**FR1.2**: The abstraction layer shall route calls to platform-specific handlers based on `options.platform` value (`"mastodon"`, `"linkedin"`, `"x"`).

**FR1.3**: The unified API shall normalize input and output formats across all platforms:
- Accept markdown content, strip markdown for X
- Accept markdown, extract title for LinkedIn
- Handle character limits by truncating/splitting as appropriate

### LinkedIn Task Handler

**FR2.1**: The LinkedIn handler shall process LinkedIn-ready content and extract platform-specific fields:
- Title: first 200 characters (max 300 characters)
- Summary: remaining content up to 3,000 characters
- Tags: comma-separated tags (max 5 tags, 25 characters each)

**FR2.2**: The LinkedIn handler shall respect LinkedIn character limits and formatting requirements:
- Title: max 300 characters, no trailing period
- Summary: max 3,000 characters, can include paragraph breaks
- Tags: max 5 tags, each max 25 characters, no duplicates

**FR2.3**: The LinkedIn handler shall authenticate using platform-specific OAuth 2.0 flow or API token, with token storage in secure configuration.

**FR2.4**: The LinkedIn handler shall include a "See full article" link to the original content in all posts.

### X (Twitter) Task Handler

**FR3.1**: The X handler shall process content and ensure it fits within 280-character limit:
- If content exceeds 280 characters, truncate with ellipsis
- If truncation needed, preserve full article link at end

**FR3.2**: The X handler shall handle hashtag formatting:
- Convert `#hashtag` to `#Hashtag` (camelCase)
- Ensure no duplicate hashtags
- Maximum 3 hashtags per post

**FR3.3**: The X handler shall use platform-specific tone (short, punchy, under 280 chars) and formatting.

**FR3.4**: The X handler shall authenticate using X API OAuth 2.0 flow with token storage in secure configuration.

**FR3.5**: The X handler shall post in batches with randomized delays (5-10 seconds between posts) to match human-like behavior.

### Platform-Specific Requirements Documentation

**FR4.1**: The system shall document platform-specific requirements for all three platforms in `docs/platform_requirements.md`:
- Character limits and field requirements
- Rate limits and backoff strategies
- Authentication requirements and session management
- Content sharing advice and tone guidelines
- Cultural norms and formatting rules

**FR4.2**: The documentation shall include:
- LinkedIn: professional tone, 2-4 sentences per post, title + summary + tags
- X: short/punchy, <280 characters, strong hook in first line, 1-2 hashtags
- Mastodon: current behavior (no changes required)

## Non-Functional Requirements

### Performance

**NFR1.1**: The X handler shall post batches within 5 seconds per batch (Success Criteria 2).

**NFR1.2**: The unified platform API shall have latency <100ms for routing to platform-specific handlers.

### Security

**NFR2.1**: All platform authentication tokens shall be stored securely (environment variables or encrypted vault) with no hardcoded tokens.

**NFR2.2**: Authentication tokens shall support automatic refresh via platform management panel (Success Criteria: "easy 'reauthentication' from platform management panel").

**NFR2.3**: Browser profiles shall use anti-detection techniques (Headless mode disabled, randomized viewports, human-like delays).

### Reliability

**NFR3.1**: The system shall implement exponential backoff for rate limit errors on all platforms.

**NFR3.2**: The system shall implement retry logic with maximum 3 attempts for transient failures (network issues, rate limits).

**NFR3.3**: The system shall log all authentication failures and require manual intervention.

### Maintainability

**NFR4.1**: The platform abstraction layer shall follow a "Open/Closed Principle" where new platforms can be added without modifying existing platform handlers.

**NFR4.2**: Platform-specific handlers shall be modular and self-contained with minimal coupling to the abstraction layer.

## Data Flow

1. **Content Ingestion**: User or AI generates content, tagged with platform target
2. **Platform Routing**: Unified `post(content, options)` API receives request
3. **Normalization**: Abstraction layer normalizes content for target platform (markdown stripping, field extraction)
4. **Authentication**: Platform-specific handler retrieves credentials from secure storage
5. **Posting**: Handler executes posting with platform-specific logic (authentication, formatting, delays)
6. **Response Capture**: Handler returns success/failure status and post ID
7. **Status Update**: Assembly Line updates content status to `published` or records failure

**Data Structures**:
- `options` dict: `{platform: "linkedin", content_id: "uuid", ...}`
- `PlatformResponse` dict: `{success: bool, platform: str, post_id: str, error: str, ...}`

## Constraints

- **Technology Stack**: Must use Playwright for browser automation, existing Python stack
- **Platform Limits**: Only LinkedIn, X, and Mastodon supported (no Instagram, TikTok, etc.)
- **Content Adaptation**: Content must be adapted per platform; no cross-posting identical text
- **Authentication**: Each platform requires separate auth flow; no shared authentication
- **Anti-Detection**: Browser profiles must remain anti-detection-compliant; no visual content generation
- **Rate Limits**: Must implement exponential backoff and monitoring for all platforms
- **Platform APIs**: APIs change frequently; require monitoring and easy reauthentication
- **Output Format**: LinkedIn requires title + summary + tags; X requires <280 characters; Mastodon unchanged
